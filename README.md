**Academic Project:** Integrated Design Project (IDP)  
**Industry Partner:** Green Afforestation International Network Sdn. Bhd. (Revongen)  
**Field Site:** Rembau Farm Paulownia Plantation Pilot Block, Negeri Sembilan, Malaysia

## 🗄️ Database Architecture: Two Primary Tables

The cloud backend (TimescaleDB / PostgreSQL) stores and processes all plantation data across **two discrete tables**:

### 1. Station Information Table (`stations`)
Stores static and user-configurable hardware node metadata:
- **`station_id`** (PK): Unique station identifier (e.g. `node-00-master`, `node-01-peri`)
- **`code`**: Visual identifier (`ST-00 (Master)`, `ST-01`, etc.)
- **`name` / `description`**: User-defined descriptive notes
- **`coordinates`**: Geographic `[latitude, longitude]`
- **`station_type`**: `'master'` (LoRaWAN + Solar) vs. `'peripheral'` (SX1262 LoRa relay)
- **`plantation_zone`**: Forestry zone (`Zone A - Center Core`, etc.)
- **`tree_tag`**: Monitored Paulownia tree ID (`PW-RMB-0101` to `PW-RMB-0122`)
- **`moisture_threshold`**: Configurable wake threshold (default `65.0%`)
- **Modify API**: Exposed via **`PUT /api/v1/stations/{id}`** and editable directly by users via the **Plantation GIS Map** interface.

---

### 2. Event Table (`events` / Time-Series Hypertable)
Stores the append-only stream of telemetry updates forwarded by the LoRaWAN gateway:
- **`event_id`** (PK): Unique record identifier
- **`station_id`** (FK): References `stations.station_id`
- **`timestamp`**: Time of capture / transmission
- **`event_type`**:
  - **`daily_heartbeat`**: Once every 24 hours. Transmitted when soil moisture is below 65%. Contains battery level, battery voltage, and soil moisture ("alive keepalive ping"). Acoustic piezo sensor is in deep sleep (`acoustic_score: null`).
  - **`15min_triggered_event`**: Every 15 minutes. Transmitted when soil moisture $\ge 65\%$. Contains full acoustic activity score ($0\text{--}100$), MFCC feature vector, ambient microclimate ($T$, $RH$), and battery data.
- **`battery_level`** & **`battery_voltage`**: Power health
- **`soil_moisture`**: Capacitive substrate probe reading (%)
- **`acoustic_score`**: Piezo vibration score (nullable: `null` when gated in deep sleep)
- **`predict_level`**: AI early-warning tier (`Safe`, `Low`, `Medium`, `High`) generated by backend inference
- **`ai_risk_score`**: Predicted escalation probability ($0\text{--}100\%$)

## ⚡ WebSocket Role: Monitoring the Event Table

The WebSocket service (`/ws/telemetry` or `/ws/events`) **only monitors the Event Table**:
1. Whenever a new row is inserted into the `events` table (either from an active station's $15\text{-minute}$ acoustic sample or from a $24\text{-hour}$ daily keepalive ping), the WebSocket automatically broadcasts:
   ```json
   {
     "type": "event_inserted",
     "event": {
       "id": "evt-1718000000",
       "stationId": "node-02-peri",
       "timestamp": "2026-10-19 21:45:00",
       "eventType": "15min_triggered_event",
       "soilMoisture": 69.5,
       "acousticScore": 68,
       "batteryLevel": 87,
       "predictLevel": "Medium"
     }
   }
   ```
2. The Vue 3 dashboard listens to this event stream, dynamically updating the station's latest sensor readings, appending the point to historical charts, and displaying incoming packets in the real-time ticker.
